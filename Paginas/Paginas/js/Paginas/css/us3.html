Tipos de Pruebas de Software

Funcionales

¿Qué hace el sistema?

Funcionales

Evalúan las acciones que el software debe realizar según las especificaciones.

Ejemplos: Iniciar sesión, procesar un pago, generar un reporte.

No Funcionales

¿Cómo lo hace el sistema?

No Funcionales

Evalúan atributos de calidad del sistema como rendimiento, seguridad o usabilidad.

Ejemplos: Pruebas de carga, estrés, usabilidad (UI/UX) y seguridad.

Pruebas Regresivas

¿Sigue funcionando todo?

Pruebas Regresivas

Comprueban que los cambios recientes en el código o correcciones de errores no hayan roto funcionalidades existentes.

Técnicas de Pruebas

Las técnicas de pruebas permiten verificar diferentes aspectos del software según su estructura interna o su comportamiento externo.

Pruebas de Caja Blanca

White-Box Testing

Pruebas estructurales que analizan la estructura interna, arquitectura y lógica del código fuente.

Pasá el mouse para conocer más

Pruebas de Caja Blanca

Enfoque principal

Se basan en el conocimiento directo de la estructura interna, el flujo de control y las sentencias del código.

Se aplican sobre todo durante la fase de pruebas de desarrollo, como pruebas de unidad y componentes.

Técnicas y métodos

Pruebas de cobertura de rutas / código: buscan garantizar que cada sentencia, rama condicional o ciclo de un componente se ejecute al menos una vez.

Análisis estático de código: permite detectar errores sintácticos, variables no inicializadas o flujos de datos anómalos antes de ejecutar el programa.

Ventajas

Permite detectar errores lógicos, de sintaxis o de flujo dentro de componentes específicos que no se perciben mediante la interfaz externa.

Es altamente automatizable mediante marcos de trabajo como JUnit dentro de esquemas como el Desarrollo Dirigido por Pruebas (TDD).

02

Pruebas de Caja Negra

Black-Box Testing

Pruebas basadas en requerimientos que verifican el comportamiento externo del sistema.

Pasá el mouse para conocer más

Pruebas de Caja Negra

Enfoque principal

El sistema se trata como una "caja negra", donde se evalúan las entradas introducidas y las salidas generadas según las especificaciones.

Es una técnica utilizada principalmente durante las pruebas de versión (release testing) y las pruebas de usuario o aceptación.

Técnicas y métodos

Pruebas basadas en requerimientos: consideran cada requerimiento funcional o especificación para derivar un conjunto de pruebas.

Partición de equivalencia: divide las entradas y salidas posibles en clases o conjuntos donde el sistema debe comportarse de forma similar.

Pruebas de escenarios o casos de uso: diseñan pruebas basadas en secuencias de interacción típicas entre los usuarios y el sistema.

Ventajas

Permite asegurar que el producto final satisfaga los requerimientos, expectativas y necesidades de los usuarios finales.

También permite validar atributos no funcionales como el desempeño, la usabilidad, la fiabilidad y la seguridad.
